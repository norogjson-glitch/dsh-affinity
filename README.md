# dsh-affinity

给 DeepSeek Harness 的**六轴关系模型**：温暖、耐心、信任、好奇、亲密、张力。它让一个角色和一个人的关系**随着对话真的在变**，而不是每轮重新猜。

零依赖，纯 JS，不需要 Rust、Postgres、向量库或任何外部服务。

## 为什么存在

大多数 AI 角色应用最后都会忘掉你是谁。关系被重置成「能塞进 prompt 的那点上下文」，人设也随着对话变长而漂移。

dsh-affinity 把那部分变得**持久**：

- 关系有六个维度，每次对话都可能推动其中几个
- 推动是**分级**的，不是「模型随口报个数」
- 长期不聊会**自然冷却**，但不会归零
- 关系会被**命名**：羁绊从「熟人」走到「灵魂伴侣」，心动从「火花」走到「挚爱」

## 六轴

| 组 | 轴 | 含义 | 特性 |
|---|---|---|---|
| 基础对 | `warmth` | 温暖 | 每轮重算，不累积 |
| 基础对 | `patience` | 耐心 | 同上 |
| 羁绊线 | `trust` | 信任 | 深维度，**永不衰减** |
| 羁绊线 | `intrigue` | 好奇 | 每天 `-0.01` |
| 心动线 | `intimacy` | 亲密 | 深维度，**永不衰减** |
| 心动线 | `tension` | 张力 | 每天 `-0.005` |

所有值 clamp 在 `[0, 1]`。

**基础对是推导出来的，不是累积的**：

```
base(level) = (level - 1) / 3
B(x)        = 1 + (10/13)·(x - 0.35)
decay(Δt)   = max(0.5, 1 - 0.02·days)

warmth   = clamp01(max(base(w_level)·B(chem), 0.25·chem) × decay)
patience = clamp01(max(base(p_level)·B(bond), 0.25·bond) × decay)
```

耦合方向是**放大**：亲密越深，表达越暖；羁绊越深，越有耐心。

低羁绊 + 高亲密 → 傲娇（不耐烦但温柔）；高羁绊 + 低亲密 → 老友（耐心但平淡）。**这两种语气是公式自己跑出来的，没有任何特判。**

## 判定协议：为什么是序数

模型是**可靠的序数评分者**，但是**不可靠的连续算术家**。问「信任涨了多少，0.0 到 1.0」会得到挤在方便小数上的数字，而且会随提示词措辞漂移；问「这是个小而真实的时刻，还是个里程碑」会得到稳定的答案。

所以：

- **羁绊线/心动线**：只报 `{grade: 0-4, direction: "up"|"down"}`

  | grade | 含义 |
  |---|---|
  | 0 | 什么都没发生（绝大多数轮次） |
  | 1 | 小而真实 |
  | 2 | 明确的推动或伤害 |
  | 3 | 罕见的重大时刻 |
  | 4 | 里程碑（极罕见） |

- **基础对**：只报绝对档位 `level: 1-3`（1=冷淡、2=基线、3=明显温暖），是**本轮的状态读数**，不是增量

**分数、标签、档位跃迁全部由引擎算。** 模型没有能力把好感度一把推到满。

## 写入管线

```
grade → 转换 → tier 衰减 → 跨线惩罚 → 阈值闸门 → clamp → 基础对重推导
```

1. **转换**：`raw = grade × unit`，羁绊 `0.0786`，心动 `0.0266`（约 3 倍差，反映评判的不对称）。负向再乘 `1.5`。
2. **tier 衰减（只削正向）**：`× [1.0, 0.70, 0.45, 0.25, 0.10]`。负向全价，任何档位都不打折。
3. **跨线惩罚**：另一条线越高，本线越难推动。`grade 0` 不收费。
4. **阈值闸门**：默认 0（每轮都提交），可配成累积后提交。

## 档位与标签

| 档 | 分数区间 | 羁绊 | 心动 |
|---|---|---|---|
| 1 | `[0.00, 0.15)` | 熟人 | 火花 |
| 2 | `[0.15, 0.35)` | 朋友 | 暧昧 |
| 3 | `[0.35, 0.62)` | 挚友 | 心动 |
| 4 | `[0.62, 0.90)` | 知己 | 恋人 |
| 5 | `[0.90, 1.00]` | 灵魂伴侣 | 挚爱 |

## 相处象限

`warmth × patience`，各以 0.5 分界：

| | 耐心 ≥ 0.5 | 耐心 < 0.5 |
|---|---|---|
| **温暖 ≥ 0.5** | 好朋友 | 快被磨光耐心的朋友 |
| **温暖 < 0.5** | 没什么交情的人 | 死对头 / 还不太认识的一个人 |

最后一格分成两种：**还没有任何互动**时是「还不太认识的一个人」，**发生过负面的事**之后才是「死对头」。刚认识的人不该被模型当成敌人。

## 安装

```bash
dsh plugin --profile web add /path/to/dsh-affinity
```

或写进 profile `package.json` 的 `dependencies` 后 `pnpm install`。装完 `cordis.patch.yml` 会自动把 `dsh-affinity` 加进 `bundles`。

## 工具

| 工具 | 用途 |
|---|---|
| `affinity_get` | 查看当前关系：六轴、两条线的档位与标签、象限、亲密阶梯 |
| `affinity_judge` | 结算一轮对话带来的关系变化（只能提交档位） |
| `affinity_relations` | 列出所有存档的关系摘要（运维用） |

## 存储

```
$DSH_HOME/affinity/<key>.json
```

一个 key 一份文件。key 默认取会话 id；多用户部署时通过 `config.storeKey` 传用户 id，**天然隔离**（每个用户的 `DSH_HOME` 本来就是独立目录）。

写入是原子的（tmp + rename）。**文件损坏时降级为全新状态，绝不抛异常** —— prompt 组装每轮都跑，不能被一个坏文件拖垮。

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `storeKey` | `''` | 覆盖存储键（多用户时传 userId） |
| `storeDir` | `$DSH_HOME/affinity` | 存储根目录 |
| `locale` | `zh` | 标签与提示文案语言 |
| `units` | `{bond: 0.0786, chem: 0.0266}` | 每档对应的分数 |
| `negFactor` | `1.5` | 负向放大倍数 |
| `crossPenaltyRatio` | `5/6` | 跨线惩罚系数 |
| `crossPenaltyStart` | `0.35` | 另一条线超过这个值才开始惩罚 |
| `deltaThreshold` | `0` | 累积到多少才提交 |
| `timeDecayRate` | `0.02` | 每天衰减率 |
| `timeDecayFloor` | `0.5` | 衰减地板 |
| `floorFactor` | `0.25` | 基础对的地板系数 |

## 出处与致谢

本插件的**算法思想**来自 [eros-engine](https://github.com/etherfunlab/eros-engine)（AGPL-3.0）的亲和度模型文档：六轴结构、纯序数判定协议、分级写入、tier 衰减、跨线惩罚、时间衰减、档位标签。

本仓库是**独立重写**（JavaScript，零依赖，无任何 eros-engine 代码），只移植了设计思路与调参值。因为思想来自 AGPL 项目，本插件同样以 **AGPL-3.0** 发布。

相比原版，本插件做了三处简化：没有 LLM judge 服务（由调用方提交档位）、没有 Postgres/pgvector（用 JSON 文件）、没有世界模拟/生命事件/ghost 机制。这些是产品层的取舍，不是算法层的缺失。
